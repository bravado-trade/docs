<Note>Sign each request with a fresh HMAC signature. The cURL and HTTP header values below are placeholders, not reusable credentials. For runnable signing code, use [request signing examples](/authentication-examples).</Note>

Moves pUSD from the venue account back to the user's deposit wallet. The destination is always the user's deposit wallet; there is no destination field. Scope `trade.perps`; `Idempotency-Key` is required.

To move the funds out of Bravado afterwards, use [`/v2/trade/withdraw`](/api/trade/withdraw).

```text
POST https://partner-api.bravadotrade.com/v2/trade/perps/withdrawals
```

### Body

<ParamField body="amount" type="string" required>
  pUSD as a decimal string with at most 6 decimal places, or `"max"` for the venue's current `withdrawable` (on [`GET /v2/trade/perps/account`](/api/trade/perps/account)).
</ParamField>

### Response

`202 Accepted`. Poll [`GET /v2/trade/perps/withdrawals/{withdrawal_id}`](/api/trade/perps/withdrawals#get-one-withdrawal) until `state` is `confirmed`.

<ResponseField name="withdrawal_id" type="string">
  The withdrawal's id. Read it back by this id.
</ResponseField>

<ResponseField name="amount" type="string">
  pUSD withdrawn.
</ResponseField>

<ResponseField name="to" type="string">
  The user's deposit wallet.
</ResponseField>

<ResponseField name="venue_withdraw_id" type="string | null">
  The venue's id for the withdrawal.
</ResponseField>

<ResponseField name="state" type="string">
  `pending`, `confirmed`, `failed`, `rejected` or `unknown`. Bravado reports `confirmed` only once the pUSD transfer to the deposit wallet is verified on chain.
</ResponseField>

<ResponseField name="venue_state" type="string | null">
  The venue's state for the withdrawal.
</ResponseField>

<ResponseField name="tx_hash" type="string | null">
  The payout transaction. It can appear while `state` is still `pending`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO-8601.
</ResponseField>

<ResponseExample>

```json 202
{
  "withdrawal_id": "8b7e6d5c-4a3b-4c2d-9e1f-0a9b8c7d6e5f",
  "amount": "48.21",
  "to": "0xDepositWallet...aabbccdd",
  "venue_withdraw_id": "77120",
  "state": "pending",
  "venue_state": null,
  "tx_hash": null,
  "created_at": "2026-10-23T16:30:00.000Z"
}
```

</ResponseExample>

### Errors

| Status | When |
| --- | --- |
| `403 Forbidden` | `OPERATION_DISABLED`: your policy does not allow withdrawals |
| `409 Conflict` | `USER_PROVISIONING_PENDING` with `reason: "withdrawable_unreadable"`: `"max"` needs a readable account; send an explicit amount |
| `422 Unprocessable Entity` | `INSUFFICIENT_BALANCE`: an amount above `withdrawable` |

Every Perps code and its retry rule: [Errors](/api/trade/perps#errors). After a `504`, list [`GET /v2/trade/perps/withdrawals`](/api/trade/perps/withdrawals) before acting again.

### Example

<CodeGroup>

```bash cURL
curl -X POST https://partner-api.bravadotrade.com/v2/trade/perps/withdrawals \
  -H "X-BRAVADO-API-KEY: $BRAVADO_API_KEY" \
  -H "X-BRAVADO-TIMESTAMP: <unix-ms>" \
  -H "X-BRAVADO-SIGNATURE: <signature-for-this-request>" \
  -H "Idempotency-Key: 6d1a8f3c-perps-withdraw-0001" \
  -H "Content-Type: application/json" \
  -d '{ "amount": "max" }'
```

</CodeGroup>
