<Note>Sign each request with a fresh HMAC signature. The cURL and HTTP header values below are placeholders, not reusable credentials. For runnable signing code, use [request signing examples](/authentication-examples). Python examples use the signed session from that page; Node.js examples use its `bravadoFetch` helper.</Note>

Returns position **state** across all wallets Bravado indexes, not just one wallet at a time. Use it to answer three questions:

- What does this wallet hold? Pass `wallet`.
- Who holds this market or token? Pass `market_id`, `condition_id` or `token_id`. Protocol, operator and relayer contracts are left out of holder lists and of the `updated_after` feed (they hold millions of mechanical positions); query one with `wallet` and its rows carry `is_operator: true`.
- What changed since I last looked? Pass `updated_after` and follow the cursor.

```text
GET https://partner-api.bravadotrade.com/trader-analytics/positions
```

<Note>
The same endpoint is also served on the Polymarket surface at `GET /v2/polymarket/positions`, where the venue is fixed to Polymarket (the `venue` parameter is not accepted). Filters, response fields, honest-unknown marks and cursor pagination are identical.
</Note>

This endpoint is the canonical, integer-exact positions surface: amounts are computed from integer micro-units, cost basis comes from the position's lot records only (a position with no lot record has a `null` cost, never an estimate), and marks are resolution-aware. The per-wallet [`/traders/{address}/positions`](/api/analytics/trader-positions) endpoints use a different calculation path (floating-point arithmetic, a fills-based cost fallback, and a separate treatment of some accounting-cohort wallets), so their figures can legitimately differ from this endpoint's. Do not expect the two to match to the last digit; use this endpoint as the source of record.

<Warning>
A request must be **bounded**. Send at least one of `wallet`, `token_id`, `condition_id`, `market_id` or `updated_after`. A request with none of them (for example `status=open` alone) returns `400` with `"code": "unbounded_scan"`.
</Warning>

### Query parameters

<ParamField query="venue" type="string" default="polymarket">
  `polymarket` or `predictfun`. Selects one venue per request; results are never merged across venues. `kalshi` returns `501` and any other value returns `400`, both with `"code": "venue_not_captured"`. See [venue semantics](#venue-semantics).
</ParamField>

<ParamField query="wallet" type="string">
  Wallet address: `0x` followed by 40 hex characters.
</ParamField>

<ParamField query="market_id" type="string">
  Venue market id. Returns every holder of every outcome token of the market.
</ParamField>

<ParamField query="condition_id" type="string">
  Condition id: `0x` followed by 64 hex characters.
</ParamField>

<ParamField query="token_id" type="string">
  Outcome token id as a decimal integer string (a 256-bit value; never send it as a JSON number).
</ParamField>

<ParamField query="status" type="string">
  `open` or `closed`. With `status=open` and no `updated_after`, open positions are listed only if their `current_value` is known and at least $1, or their `current_value` is unknown (the mark is unknown, or the held balance is unknown, `open_value_source` = `unknown_book_unseeded`, and the mark does not fix the value at 0). An unknown value is never dropped as worthless; a known value of `0.000000`, such as a resolved-losing position, is dropped. This is the same rule the `active_positions` count on the [trader profile](/api/analytics/trader) uses, but that count is a snapshot (see `active_positions` on the trader profile), so the two can differ by trades since the snapshot.
</ParamField>

<ParamField query="min_timestamp" type="integer">
  Unix **milliseconds**. Only positions whose `last_updated_at` is at or after this time.
</ParamField>

<ParamField query="max_timestamp" type="integer">
  Unix **milliseconds**. Only positions whose `last_updated_at` is at or before this time.
</ParamField>

<ParamField query="min_block" type="integer">
  Only positions whose latest on-chain activity is at or after this block.
</ParamField>

<ParamField query="max_block" type="integer">
  Only positions whose latest on-chain activity is at or before this block.
</ParamField>

<ParamField query="min_position_value" type="string">
  USDC decimal with at most 6 decimal places (for example `"25"` or `"12.5"`). Applied to the **live** `current_value`. Positions whose mark is unknown cannot pass a value floor and are excluded; they are counted in `unpriced_positions`. Replaces the $1 `status=open` admission.
</ParamField>

<ParamField query="updated_after" type="integer">
  Unix **milliseconds**, exclusive. Returns positions whose state changed after this time. See [state sync](#sync-position-state-with-updated_after).
</ParamField>

<ParamField query="include_uncatalogued" type="boolean" default="false">
  `true` or `false`; any other value returns `400` with `"code": "invalid_include_uncatalogued"`. With `status=open`, also lists open positions whose token is not in the market catalogue **and** has no mark (`identity_source` `uncatalogued`, `mark_source` `unknown`, null price and value). By default they are left out of the listing and counted in `uncatalogued_count`. It has no effect on the `updated_after` sync axis, which carries every row, or on a read without `status=open`, which lists them flagged.
</ParamField>

<ParamField query="limit" type="integer" default="100">
  Page size, 1 to 1000. Values outside the range return `400`.
</ParamField>

<ParamField query="cursor" type="string">
  The opaque `next_cursor` from the previous page. Send it unchanged with the **same** filters. A cursor replayed with different filters, or against a different ordering, returns `400` with `"code": "cursor_mismatch"`.
</ParamField>

`min_timestamp`, `max_timestamp`, `min_block` and `max_block` all describe the position's **latest activity**: its most recent economic event (a fill, split, merge, redemption or settlement). Unknown query parameters and repeated parameters return `400`.

### Position fields

Money and share fields are exact decimal **strings** with 6 decimal places, computed from integer micro-units. Parse them with a decimal type. See [numeric conventions](/reference/numeric-conventions).

| Field | Type | Description |
|---|---|---|
| `venue` | string | `polymarket` or `predictfun`. |
| `wallet` | string | Lowercase `0x` address. |
| `market_id` | string or null | `null` when the token is not yet mapped to a market. |
| `condition_id` | string or null | `0x` condition id; `null` when unknown. |
| `token_id` | string | Decimal outcome token id. |
| `outcome` | string or null | Outcome label (for example `Yes`); `null` when unlabelled. |
| `shares` | string or null | Shares held now; `"0.000000"` for closed positions. `null` when `open_value_source` is `unknown_book_unseeded`. |
| `avg_entry_price` | string or null | Remaining cost basis per **covered** share, in USDC. `null` when cost is unknown. |
| `cost_basis` | string or null | Remaining cost basis in USDC. `null` when cost is unknown. Never `"0.000000"` as a stand-in for unknown. |
| `current_price` | string or null | Live mark in USDC per share, `0` to `1`. `null` when `mark_source` is `unknown`. |
| `current_value` | string or null | `shares` times `current_price`. `null` when the mark is unknown, or when `open_value_source` is `unknown_book_unseeded` (held balance unknown) unless the mark is a resolution price of exactly `0.000000`, in which case the value is a known `"0.000000"` whatever is held. |
| `realized_pnl` | string or null | Realized PnL in USDC (signed). `null` when `realized_pnl_source` is `not_in_projection`. See [venue semantics](#venue-semantics). |
| `realized_pnl_source` | string | Where `realized_pnl` comes from. `fifo_fills`: the sum over the position's recorded fills. `not_in_projection`: the positions projection holds no fills for this key (not a claim that the wallet never traded the token), and `realized_pnl` is `null`. Always present. |
| `unrealized_pnl` | string or null | On **covered** shares only: `min(shares, covered) × (current_price − cost per covered share)`. `null` when the mark or cost is unknown. |
| `status` | string | `open` or `closed`. |
| `last_updated_at` | integer | Unix **milliseconds** of the position's latest economic event. |
| `mark_source` | string | `resolution`, `quote`, `trade` or `unknown`. |
| `mark_ts` | integer or null | Unix seconds of the quote or trade the mark rests on. `null` for `resolution` and `unknown`. |
| `open_value_source` | string | `book`, `fifo_lot` or `unknown_book_unseeded`. |
| `is_operator` | boolean | `true` when the wallet is a protocol, operator or relayer contract rather than a trader. Always present. Such wallets never appear in holder lists or the `updated_after` feed; they are returned only when you ask for them with `wallet`. |
| `collateral` | string or null | The ERC-20 the position token was minted with, as a lowercase `0x` address. `null` when it is not recorded (see `collateral_source`); never guessed from the venue's usual collateral. |
| `collateral_source` | string | `pm_ctf_position` when `collateral` is known, `unknown` when it is `null`. Always present. |
| `canonical` | boolean or null | `true`: the token is the market's catalogued outcome token. `false`: the token was minted with a **different collateral** than the catalogue lists (for example native USDC, pUSD or USDC.e on a NegRisk market); it is labelled, grouped and priced by its catalogued sibling of the same market outcome, and `token_id` is still the real on-chain id. `null`: unknown. `null` is **not** `false`. Always present. |
| `identity_source` | string | How `market_id`, `condition_id` and `outcome` were resolved: `catalogue` (the token is catalogued), `collateral_sibling` (via its catalogued sibling, `canonical` is `false`), or `uncatalogued` (the market is not catalogued yet: `market_id`, `condition_id` and `outcome` are `null`; `mark_source` is `unknown` unless a defensible last-trade mark exists, in which case the position is priced and listed as usual). Always present. |
| `cost_alloc_source` | string or null | How the cost of the open lots was allocated when it came from splitting a bundle (PMWAS §6.4); the weakest source among the lots, one of `PROTOCOL_FIXED`, `RELATIVE_FAIR_VALUE`, `COMPLETE_SET_PARITY`, `EQUAL`, `IMPLIED_RFV`, `BASIS_RECOVERED`. `null` means **no allocation source recorded**: it is not a claim of a direct purchase, and it is never `EQUAL`. Always present. |
| `cost_alloc_evidence` | string or null | The evidence level of the allocation (PMWAS Appendix G). `"C"` for `EQUAL` (an equal split of the bundle's cost) and for `BASIS_RECOVERED` (the cost a NegRisk convert's cash leg did not recover; not a fair value). `"D"` for `IMPLIED_RFV` (model-grade: estimated from the burned legs' market prices). `null` for `PROTOCOL_FIXED`, `RELATIVE_FAIR_VALUE` and `COMPLETE_SET_PARITY`, which are not graded here. Always present. |
| `recognized_capital` | string or null | USDC, signed 6-decimal string. Proceeds on shares whose cost basis is unknown, recognized as **capital** (PMWAS §7.7(b)). It is **not** profit or loss and is never included in `realized_pnl`, `unrealized_pnl` or any total. `"0.000000"` means nothing was recognized. `null` when it is unknown. Always present. |
| `recognized_capital_source` | string | `fifo_fills` when `recognized_capital` is a figure, `pre_convention` when it is `null` (the position's records predate the convention, or the book never saw the position). Always present. |

### Marks and unknown values

Marks are computed **live on every request** (responses are not cached), in this order: the market's resolution payout, then a fresh quote, then the last real trade, then **unknown**. They are never stored on the position, so a price tick does not change `last_updated_at`.

- When no defensible mark exists, `mark_source` is `unknown` and `current_price`, `current_value` and `unrealized_pnl` are JSON `null`. The keys are always present. Unknown is never reported as `0`.
- A held token that is not in the market catalogue and has no mark is **uncatalogued**: its market, outcome and value are unknown. It is not valued at `0` and is not counted as a position in a `status=open` listing (see `include_uncatalogued` and `uncatalogued_count`). Such tokens are part of `unpriced_positions`.
- When the cost basis cannot be determined, `cost_basis` and `avg_entry_price` are `null`.
- When `open_value_source` is `unknown_book_unseeded` (a Polymarket wallet whose on-chain balances have not been indexed yet), `shares`, `cost_basis`, `avg_entry_price` and `unrealized_pnl` are `null`, and so is `current_value`, with one exception: when the mark is a **resolution** price of exactly `0.000000` (a resolved-losing token), `current_value` is `"0.000000"`, because zero times any balance is zero. A winning, quoted or traded mark leaves the value unknown, since the balance is. The row's `status` is a placeholder in that case; rely on `open_value_source`.
- When `realized_pnl_source` is `not_in_projection` (the positions projection holds no fills for the key), `realized_pnl` is `null`: the realized result is unknown here, not zero.
- `collateral`, `canonical`, `cost_alloc_source`, `cost_alloc_evidence` and `recognized_capital` are `null` when unknown, with a provenance sibling (`collateral_source`, `identity_source`, `recognized_capital_source`). Rows that have not been refreshed since these fields were introduced read as unknown, never as a default.
- A `canonical: false` position is priced by its catalogued sibling, so its `current_price` and `mark_source` are those of the same market outcome.
- A position with `shares` of `"0.000000"` has a `current_value` and `unrealized_pnl` of exactly `"0.000000"`: nothing held is worth nothing, which is known.

### Pagination

Results are paged with an opaque keyset `cursor`. Do not parse or construct it.

<Note>
**Use the cursor for an exact enumeration.** `/positions` has no `offset`: it is cursor-only, and the cursor resumes after the last row served, so a position that changes while you page is neither skipped nor served twice. The per-wallet routes [`/traders/{address}/positions`](/api/analytics/trader-positions) and [`/traders/{address}/positions/active`](/api/analytics/trader-positions-active) page with `offset` over a live set: if positions open, close or re-rank between two requests, offset paging can skip rows or return a row twice. To enumerate a wallet exactly, page `/positions?wallet=...&status=open` with `cursor` instead.
</Note>

- Follow `next_cursor` until it is `null`. A page can hold fewer than `limit` rows while `next_cursor` is still non-null, for example when a value floor discards many candidates.
- Send the same filters on every page. Changing `limit` between pages is allowed.
- Row order is the query's key order, not value order: by token then wallet for market and token queries, by token for a wallet query, and by `last_updated_at` for `updated_after`. Sort client-side if you need ranking by value.

### Sync position state with `updated_after`

Use `updated_after` to keep a local copy of position **state** current.

1. Start from `updated_after=0`, or from the time you last finished a sync.
2. Page with `cursor` until `next_cursor` is `null`. Each position appears **once**, at its latest state, even if it changed several times since your last sync.
3. Remember the largest `last_updated_at` you received. For the next sync, use that value **minus a safety margin** (for example 15 minutes) as `updated_after`, and apply rows idempotently by `(wallet, token_id)`, keeping the row with the greater `last_updated_at`.

`last_updated_at` is the on-chain time of the position's latest event, not the time the row became visible to the API. A row for a slightly older block can therefore appear after you have already seen a newer one; the overlap makes that harmless, and the idempotent apply makes the re-read free.

`updated_after` syncs state, not prices. A position row changes only when the wallet's position changes on-chain. `current_price`, `current_value` and `unrealized_pnl` are always as of `served_at`; to re-price positions you already hold, query them again with `token_id` (all holders of that token) or `wallet`. The change feed does not drop positions that decay to dust, so `status=open` admission is not applied on this axis.

### Venue semantics

| | Polymarket | predict.fun (`venue=predictfun`) |
|---|---|---|
| `shares` source | On-chain `balanceOf` book (`open_value_source` is `book`) | FIFO lot state (`open_value_source` is `fifo_lot`); there is no `balanceOf` book |
| `unknown_book_unseeded` | Possible | Never |
| `current_value` of an unseeded row | `null`, except a known `"0.000000"` for a resolution mark of `0.000000` | n/a (never unseeded) |
| `mark_source` | `resolution`, `quote`, `trade`, `unknown` | `resolution`, `quote`, `unknown` (no `trade` tier) |
| `realized_pnl` | As the PnL engine books it for the wallet | **Net of fees** |
| `collateral`, `canonical` | Known for every token the CTF position map holds. A token minted with a non-catalogue collateral is served (`canonical: false`) with its `collateral` | The CTF position map is not populated for predict.fun yet: `collateral` is `null` (`collateral_source: "unknown"`) and `canonical` is `true` or `null`, never `false` |
| `cost_alloc_source`, `recognized_capital` | As the PnL engine records them | `null` (`recognized_capital_source: "pre_convention"`) until the engine writes them for this venue |

`open_shares` and `resolved_unredeemed_shares`, which decompose a `balanceOf` balance on the per-wallet endpoints, are not part of this response on either venue.

Partner keys need the venue enabled for the request: `venue=predictfun` requires `predictfun` in your enabled venues (otherwise `403 VENUE_NOT_ENABLED`). The same data is available on the predict.fun mount, `GET /trader-analytics/predict/positions`, where `venue` defaults to `predictfun`.

## Errors

Errors return `{"error": "...", "code": "..."}`.

| Status | `code` | Meaning |
|---|---|---|
| 400 | `unbounded_scan` | None of `wallet`, `token_id`, `condition_id`, `market_id`, `updated_after` was sent. |
| 400 | `invalid_include_uncatalogued` | `include_uncatalogued` was not `true` or `false`. |
| 400 | `invalid_wallet`, `invalid_token_id`, `invalid_condition_id`, `invalid_market_id`, `invalid_status`, `invalid_limit`, `invalid_min_position_value`, `invalid_min_timestamp`, `invalid_max_timestamp`, `invalid_min_block`, `invalid_max_block`, `invalid_updated_after`, `invalid_range` | A parameter failed validation. `invalid_range` means a `min_*` bound is greater than its `max_*` bound. |
| 400 | `unknown_parameter`, `duplicate_parameter` | An unsupported or repeated parameter. |
| 400 | `invalid_cursor`, `cursor_mismatch` | The cursor is malformed, or was issued for different filters or ordering. |
| 400 / 501 | `venue_not_captured` | Unknown venue (400) or `kalshi` (501). |

See the [Error reference](/reference/errors) for the common error envelope.

### Position history and streaming

Position **history** (how a position evolved over time) and a position-update **WebSocket** are not part of this endpoint. Bravado retains the underlying change data, so both are feasible as a separate future addition.
