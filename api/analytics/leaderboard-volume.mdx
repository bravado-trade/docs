Returns traders ranked by USDC trading volume for the requested window. The ranking runs in the database over the complete candidate set on the served column, with a deterministic wallet tie-break, so pages never overlap or skip rows.

```text
GET https://partner-api.bravadotrade.com/trader-analytics/leaderboard/volume
```

### Query Parameters

<ParamField query="window" default="24h" type="string">
  Rolling time window. One of `1h`, `4h`, `24h`, `7d`, `30d`, `90d`, `365d`, `all`.
</ParamField>

<ParamField query="limit" default="50" type="integer">
  Number of traders to return. Maximum 500.
</ParamField>

<ParamField query="offset" default="0" type="integer">
  Offset for pagination. See [Pagination](/reference/pagination). Passing `order=asc` is usually cheaper than a large offset — see the note below.
</ParamField>

<ParamField query="sort" default="volume_usdc" type="string">
  Ranking column: `volume_usdc` (USDC notional), `trades` (fill count), or `volume_shares` (contracts traded). This board carries no PnL fields, so a PnL sort key from [`GET /leaderboard`](/api/analytics/leaderboard) is rejected with `400`.
</ParamField>

<ParamField query="order" default="desc" type="string">
  `desc` or `asc`. `order=asc` reads the **bottom** of the board directly — e.g. the least-active traders — without walking pages backward from an offset you have to discover first.
</ParamField>

<ParamField query="min_trades" default="0" type="integer">
  Minimum trade count to be included in the candidate set. Note this board's default is `0`, while [`GET /leaderboard`](/api/analytics/leaderboard)'s default is `5` — pass the same value to both endpoints to compare over the same set of traders.
</ParamField>

### Errors

| Status | When |
| --- | --- |
| `400 Bad Request` | Invalid `window`, `sort`, `order`, `limit`, or `offset` value |
| `401 Unauthorized` | Missing or invalid Bearer token |
| `429 Too Many Requests` | Rate limit exceeded, see `Retry-After` header |

See the [Error reference](/reference/errors).


### Reading the bottom of the board

Because `total` is now on the response, finding the end of the board no longer requires a binary search over `offset`. If you need the worst-performing or least-active traders specifically, `sort=trades&order=asc` (or `sort=volume_usdc&order=asc`) reads them directly from the front of an ascending sort — which is meaningfully cheaper than a large `offset` against a descending one, since ClickHouse still has to produce every row before a large offset even though it only returns the page after it.
