Connect using a Market Data credential with `stream.read` from an organisation with an eligible paid plan. Sign the upgrade with [HMAC](/authentication); your organisation must also have access to the venue. [Create an account](https://console.bravadotrade.com/signup) or manage access in [Console](https://console.bravadotrade.com/products/websockets).

| Venue | WebSocket URL |
| --- | --- |
| Polymarket | `wss://partner-api.bravadotrade.com/stream/polymarket/partner` |
| Predict.fun | `wss://partner-api.bravadotrade.com/stream/predictfun/partner` |
| Kalshi | `wss://partner-api.bravadotrade.com/stream/kalshi/partner` (books only, see [Kalshi](#kalshi)) |

## Subscribe

Use the venue's outcome token ID, not its event or market ID. On Predict.fun this is the outcome's `onChainId`. On Kalshi it is the market ticker, see [Kalshi](#kalshi).

Install `ws` (`npm install ws`), set `BRAVADO_API_KEY`, `BRAVADO_API_SECRET` and `BRAVADO_ASSET_ID`, then run this as a Node.js `.mjs` file. Keep the secret server-side.

```javascript Node.js
import WebSocket from "ws";
import { createHash, createHmac } from "node:crypto";

const venue = "polymarket"; // or "predictfun" / "kalshi", if enabled for your organisation
const asset = process.env.BRAVADO_ASSET_ID;
const key = process.env.BRAVADO_API_KEY;
const secret = process.env.BRAVADO_API_SECRET;
if (!asset || !key || !secret) throw new Error("Set asset ID, API key and secret");
const path = `/stream/${venue}/partner`;
const timestamp = String(Date.now());
const payload = [timestamp, "GET", path, createHash("sha256").update("").digest("hex")].join("\n");
const signature = createHmac("sha256", secret).update(payload).digest("hex");
const ws = new WebSocket(`wss://partner-api.bravadotrade.com${path}`, {
  headers: {
    "X-BRAVADO-API-KEY": key,
    "X-BRAVADO-TIMESTAMP": timestamp,
    "X-BRAVADO-SIGNATURE": signature,
  },
});
ws.on("open", () => ws.send(JSON.stringify({
  op: "sub",
  streams: [`book:${asset}`],
})));
ws.on("message", data => {
  const frame = JSON.parse(data.toString());
  if (frame.type === "error") {
    console.error(frame.code, frame.message);
    return;
  }
  if (frame.channel !== "book") return;
  if (frame.type === "snapshot" || frame.type === "delta") {
    // Both frame types carry complete sides: replace your local book.
    console.log(frame.asset, frame.seq, frame.bids, frame.asks);
  } else if (frame.type === "status") {
    console.log(frame.state, frame.reason);
  }
});
ws.on("error", error => console.error(error.message));
const stop = setTimeout(() => ws.close(), 30_000);
ws.once("close", () => clearTimeout(stop));
```

Subscribe to multiple tokens with a `streams` array. Unsubscribe with `{"op":"unsub","streams":["book:<OUTCOME_TOKEN_ID>"]}`. The authenticated route limits an organisation to 200 distinct assets across its keys and connections. An already-subscribed asset does not add another distinct asset to that quota.

Data delivery consumes [WebSocket credits](/api-credits#authenticated-websocket-credits). The sample closes after 30 seconds to bound usage. Generate a fresh signature and resubscribe on every reconnect; use backoff rather than retrying authentication failures continuously. Node's `ws` responds to protocol pings automatically.

The legacy `/stream/{venue}/market` and `/orderbook-feed/ws` routes have a separate Terminal access contract. Use the authenticated routes above for Console integrations and usage attribution.

## Read the messages

Book frames include `channel: "book"`, `venue`, `asset`, `type`, `seq`, `ts` and, for snapshots and deltas, `bids` and `asks`.

- Each price level is `[price, size]`, with both values encoded as decimal strings.
- **Both snapshots and deltas contain complete sides**, not level patches. Replace the previous sides on each frame.
- Bids are descending; asks are ascending. A transient crossed book is possible during venue updates.
- Sequence numbers are per venue and asset. A snapshot resets local book state; do not infer ordering across venues.
- `ts` is Bravado's timestamp in milliseconds. `upstreamTs` is the venue timestamp when available, otherwise `null`.
- Status frames distinguish `live` and `degraded`. Check `reason`; a connection or status frame alone does not mean a fresh book has arrived.

Reconnect and resubscribe after a disconnection. Do not display a buffered book as fresh while the stream is degraded.

## Kalshi

Kalshi is a **book-only** venue on Bravado: order books and nothing else. There is no Kalshi trading, copytrade or trader-analytics surface, and there is no Kalshi live-trades feed. See [venue coverage](/markets/overview#product-coverage-by-venue).

| | |
| --- | --- |
| WebSocket URL | `wss://partner-api.bravadotrade.com/stream/kalshi/partner` |
| Subscription | `book:<asset>`, where `asset` is the Kalshi market ticker |
| Prices and sizes | Decimal strings, as on the other venues |
| Required scope | `stream.read` |
| Entitlement | A Kalshi **data** grant, separate from the trading-venue entitlement |
| Live trades | Not available |

Everything in [Connect](#subscribe) and [Read the messages](#read-the-messages) applies unchanged: the same HMAC upgrade, the same `streams` array, the same `channel`/`venue`/`asset`/`type`/`seq`/`ts` envelope, and the same shared asset quota.

<Note>
  **`GET /stream/capabilities` is the contract.** Read it rather than hard-coding this page. The `kalshi` row, for an organisation holding the data grant:

  ```json
  {
    "venue": "kalshi",
    "implemented": true,
    "entitled": true,
    "upstream_registered": true,
    "book_path": "/stream/kalshi/partner",
    "subscription": "book:<asset>",
    "trades_path": null,
    "combos_path": null,
    "book_delta_semantics": "full_book_replacement",
    "sequence_domain": "bravado_delivery_per_asset",
    "snapshot_resets_sequence": true,
    "upstream_history_completeness_attested": false,
    "historical_depth_export_path": null,
    "historical_depth_required_scope": null,
    "fee_schedule_path": null,
    "market_rules_path": null,
    "reason": "check_per_asset_stream_status"
  }
  ```

  Three of those fields are separate facts, and the `reason` names whichever is missing: `implemented` (Bravado built the endpoint), `upstream_registered` (this deployment has the upstream wired) and `entitled` (your organisation holds the grant). A `reason` of `check_per_asset_stream_status`, as above, means all three are satisfied and any remaining problem is per-asset.

  `entitled` is driven by your Kalshi **data** grant, a different column from the trading-venue entitlement — holding Polymarket or Predict.fun access does not imply Kalshi. The `null` fields are not omissions: trades, combos and historical depth exports are Polymarket-only surfaces.
</Note>

<Info>
  **Kalshi uses `full_book_replacement`, the same as the other two venues.** Both snapshots and deltas carry complete sides: replace your local book on each frame, do not patch it.

  Confirmed by joint decision with the market-data side, 2026-10-27, after the normalisation was reviewed — Kalshi's native increments are summed api-side so the customer wire is level-set on every frame. Read `book_delta_semantics` from `GET /stream/capabilities` anyway: it is the live per-venue answer, and a venue added later need not match.
</Info>

## Coverage

These routes serve live order books. Predict.fun subscriptions require an indexed binary market and its outcome token IDs. Kalshi serves books only, see [Kalshi](#kalshi). The [enriched trade feed](/api/market-data/trade-feed) is a separate Polymarket feed; book changes are not executions.

`GET /stream/capabilities` is the authoritative, per-organisation answer for every venue on this page. It separates three facts that are easy to conflate: `implemented` (Bravado built the endpoint), `upstream_registered` (this deployment has the venue's upstream wired), and `entitled` (your organisation bought it). Its `reason` field names which of the three is missing.

For historical L2 or bulk extracts, see [historical data and custom delivery](/api/market-data/historical-data).
