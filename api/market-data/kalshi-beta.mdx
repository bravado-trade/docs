The Kalshi beta serves **a selected, changing set of markets**, using the shared [order-book message format](/api/market-data/venue-order-books). It does not cover every open Kalshi market. BTC and ETH 15-minute contracts are included when present in the ready inventory.

Discover the current tickers through signed `GET /stream/kalshi/partner/coverage`, using the same Market Data credential as the WebSocket. The response includes `scope`, `ready`, `pending`, `inactive` and `retired` lists, counts, `as_of`, cache age and the source generation. `all_open_markets` is explicitly `false`; a ready inventory does not prove that an individual quote is fresh. Check the stream status and quote timestamp too.

The default page contains up to 500 market tickers. Follow `next_cursor` with a signed, canonically encoded query until it is null. If the inventory changes between pages, HTTP409 asks you to restart pagination. HTTP503 means coverage cannot currently be verified; do not treat it as an empty universe. Retired contracts and pending markets must not be treated as live books.

Read [native market metadata](/api/market-data/kalshi-native) for exact open, close and settlement times. Re-read coverage to discover replacement tickers when short-duration contracts close; subscribing to one ticker does not subscribe you to its replacements.

## Check access first

Use an active **Market Data** credential with `stream.read`, an eligible paid plan and an explicit Kalshi data grant. A Data REST key is a different credential class. Keep the secret on your server.

Before connecting, make a signed `GET /stream/capabilities`. The `kalshi` row must have `implemented`, `upstream_registered` and `entitled` set to `true`. Then connect to `wss://partner-api.bravadotrade.com/stream/kalshi/partner`. Availability is still per market: inspect stream status and wait for a snapshot before using a book.

## Server example

Install `ws`, set `BRAVADO_API_KEY` and `BRAVADO_API_SECRET`, and run this as a Node.js `.mjs` file. The example discovers a ready market, subscribes to it and closes after 30 seconds to bound usage.

```javascript Node.js
import WebSocket from "ws";
import { createHash, createHmac } from "node:crypto";

const key = process.env.BRAVADO_API_KEY;
const secret = process.env.BRAVADO_API_SECRET;
if (!key || !secret) throw new Error("Set your Market Data key and secret");
const origin = "https://partner-api.bravadotrade.com";
const headers = path => {
  const timestamp = String(Date.now());
  const payload = [timestamp, "GET", path,
    createHash("sha256").update("").digest("hex")].join("\n");
  return {
    "X-BRAVADO-API-KEY": key,
    "X-BRAVADO-TIMESTAMP": timestamp,
    "X-BRAVADO-SIGNATURE": createHmac("sha256", secret).update(payload).digest("hex"),
  };
};
const response = await fetch(`${origin}/stream/capabilities`, {
  headers: headers("/stream/capabilities"), redirect: "error",
  signal: AbortSignal.timeout(8_000),
});
if (!response.ok) throw new Error(`Capabilities refused (${response.status})`);
const capabilities = await response.json();
const kalshi = capabilities.venues?.find(row => row.venue === "kalshi");
if (!kalshi?.implemented || !kalshi.upstream_registered || !kalshi.entitled)
  throw new Error("Kalshi is not available for this organisation right now");

const coveragePath = "/stream/kalshi/partner/coverage";
const coverageResponse = await fetch(`${origin}${coveragePath}`, {
  headers: headers(coveragePath), redirect: "error",
  signal: AbortSignal.timeout(8_000),
});
if (!coverageResponse.ok)
  throw new Error(`Coverage unavailable (${coverageResponse.status})`);
const coverage = await coverageResponse.json();
const ticker = coverage.ready?.[0];
if (!ticker || coverage.stale) throw new Error("No verified ready market on this page");

const query = new URLSearchParams({ streams: `book:${ticker}` });
const path = `/stream/kalshi/partner?${query}`;
const ws = new WebSocket(`wss://partner-api.bravadotrade.com${path}`, {
  headers: headers(path), handshakeTimeout: 8_000,
  followRedirects: false, rejectUnauthorized: true,
});
ws.on("message", raw => {
  const frame = JSON.parse(raw.toString());
  if (frame.type === "error") { console.error(frame.code); return; }
  if (frame.type === "status") { console.log(frame.state, frame.reason); return; }
  if (frame.channel === "book" && ["snapshot", "delta"].includes(frame.type))
    console.log(frame.asset, frame.seq, frame.bids, frame.asks, frame.quote);
});
ws.on("error", () => console.error("WebSocket connection failed"));
const stop = setTimeout(() => ws.close(), 30_000);
ws.once("close", () => clearTimeout(stop));
```

Use the market ticker after `book:`, not an outcome token ID. You can request multiple ready tickers on one connection, within your account limits. [Authentication helpers](/authentication-examples) cover signing; the [shared WebSocket guide](/api/market-data/venue-order-books) covers subscription commands, reconnection and credits. This example is server-side; never put its HMAC secret in browser code.

## Use the book safely

- Prices and sizes are **decimal strings**, including fractional quantities. Preserve them with exact decimal arithmetic.
- Both `snapshot` and `delta` carry **complete** `bids` and `asks`. Replace your previous sides; do not add these quantities as increments. Empty or one-sided books can be valid.
- `seq` is a Bravado sequence per asset. A snapshot starts a new book state. A missing or unexpected sequence means you must stop using that state and reconnect for a new snapshot.
- `quote.sourceWallUtc` is the source's receive time; `quote.venueTs` is the venue timestamp when present. Sending-clock fields remain separate. `ts` is the API timestamp, not the age of the quote. Protocol pings keep the connection alive without making a quiet quote newer.
- On `degraded`, discard trust in the book. A later `live` status or open socket alone does not restore it: wait for a fresh snapshot. Reconnect with a fresh signature and backoff after a disconnection.

This beta provides order books only, with no live-trades channel. It does not promise an uninterrupted feed, automatic replacement of client subscriptions, a latency advantage over Kalshi, or complete historical coverage. [Native REST data](/api/market-data/kalshi-native) and [captured book history](/api/market-data/kalshi-history) have separate coverage contracts.
