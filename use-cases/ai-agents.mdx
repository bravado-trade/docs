## The problem

Autonomous agents (LLM-driven or otherwise) that trade prediction markets need several things at once: a realtime market-data feed, a way to reason about traders and wallet state without ambiguity, a safe execution surface with strong idempotency guarantees, and awareness of how markets settle. Wiring an agent to a venue's raw contracts requires custom code to smooth all of that.

## The Bravado AI stack

Bravado is prediction-market infrastructure, and an agent reaches different parts of it through the right interface for each job. For an architecture-level walkthrough, see [Build with AI](/build-with-ai).

| Interface | What the agent uses it for |
| --- | --- |
| [Market Data / WebSockets](/products/market-data) | **Realtime market state**: live order books, trades, and prices streamed over WebSockets, so an agent reacts to the market instead of polling |
| [MCP Server](/products/mcp-server) | **Agent-native intelligence**: read-only, OAuth-authorized tools for leaderboards, trader profiles, PnL, positions, and read-only SQL, with no REST wrapper to write |
| [Trader Data API](/products/data-api) | **Programmatic analytics** over REST: wallet history, PnL, cost basis, and leaderboards for grounded context |
| [Trade API](/products/trade-api) | **Execution**: placing and cancelling orders, reading positions and balances. This is the only surface that acts |
| [UMA API](/products/uma-api) | **Resolution context**: settlement state, so an agent does not treat a concluded event as a redeemable position |

<Note>
  **Realtime agents lead with Market Data**, MCP and the Trader Data API supply intelligence, and **execution happens only through the Trade API**, never through MCP, which is read-only. Keep those boundaries in your architecture.
</Note>

Bravado also publishes machine-readable docs (`llms.txt`, `llms-full.txt`) and a **read-only** hosted MCP server at `https://mcp.bravadotrade.com/mcp`, authorized with OAuth 2.1. Every mutating Trade API call requires an `Idempotency-Key`, so agents that retry on failure cannot double-execute. See [Idempotency](/reference/idempotency).

<Note>
  The UMA API endpoint reference is still being written. Until it lands, resolution state has to be inferred from position data. See [UMA API](/products/uma-api).
</Note>

## Worked example

An LLM tool-calling function that lets an agent evaluate a market and place a scaled position:

```python
import os, uuid, requests

API = "https://partner-api.bravadotrade.com"
H = {"Authorization": f"Bearer {os.environ['BRAVADO_API_KEY']}", "Content-Type": "application/json"}

def place_scaled_order(symbol: str, side: str, confidence: float, max_notional_usd: float):
    """Tool an agent can call.
    confidence: 0.0 to 1.0. Higher confidence -> larger position, up to max_notional_usd.
    """
    notional = str(round(max_notional_usd * confidence, 2))

    r = requests.post(
        f"{API}/v2/trade/order",
        headers={**H, "Idempotency-Key": str(uuid.uuid4())},
        json={
            "symbol": symbol,
            "side": side,
            "type": "MARKET",
            "quote_amount": notional,
        },
    )
    r.raise_for_status()
    return r.json()

def get_position(symbol: str):
    """Agent can inspect its own state."""
    r = requests.get(f"{API}/v2/trade/positions", headers=H, params={"symbol": symbol})
    r.raise_for_status()
    return r.json()
```

Register these as tools with the agent framework (LangChain, OpenAI function-calling, Anthropic tool use, etc.) and constrain `max_notional_usd` at the tool boundary so the agent cannot exceed a budget per action.

## Safety patterns

- **Per-tool notional caps.** Enforce dollar limits at the tool layer, not in the agent's prompt.
- **Dry-run mode.** Route to a test wallet or a preview endpoint during development.
- **Cooldowns and daily caps.** Reject tool calls that exceed a rolling limit.
- **Full audit trail.** Every mutating call has an idempotency key. Log them per agent session for post-hoc review.
