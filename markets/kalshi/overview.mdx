Kalshi is a US event exchange regulated by the CFTC as a designated contract market. Contracts
settle at \$1 if the event happens and \$0 if it does not, so a live price reads as an implied
probability — the same shape as the other venues on this page. Unlike Polymarket and Predict.fun
it is not a conditional-token market on a public chain: contracts are exchange-listed instruments,
identified by a market ticker rather than an on-chain token id.

<Info>
  **The Kalshi live order-book feed is available** across a bounded, changing cohort of markets — dozens at a time, not every open Kalshi market. Discover the served set through signed `GET /stream/kalshi/partner/coverage`; `all_open_markets` is `false`. Check `GET /stream/capabilities` for your organisation's `entitled` state before connecting.
</Info>

Kalshi is a **Market Data venue only**. There is no Kalshi trading, copy-trading or trader
analytics on Bravado, and none is in rollout — see [product coverage](#product-coverage) below.

## Order-book feed

The [Kalshi order-book feed](/api/market-data/kalshi-beta) serves a bounded, changing cohort of markets over the shared authenticated [order-book format](/api/market-data/venue-order-books): a snapshot then sequenced full-book replacements, both sides quoted as exact decimal strings. It is not every open Kalshi market — discover the current set through signed `GET /stream/kalshi/partner/coverage`, which returns the served `scope`, the `ready` / `pending` / `retired` lists and `all_open_markets: false`. Short-duration contracts roll over; re-read coverage to find replacement tickers.

## Checking the live state

`GET /stream/capabilities` is the contract for what this venue serves, per organisation, right
now. It separates three facts that are easy to read as one:

| Field | Means |
| --- | --- |
| `implemented` | Bravado has built the endpoint for this venue |
| `upstream_registered` | the venue's upstream is wired in this deployment |
| `entitled` | your organisation holds the entitlement |
| `reason` | which of the three is missing, when the venue is not usable |

For Kalshi today, `implemented` and `upstream_registered` are `true`; connect once your
organisation's `entitled` state is `true`. Availability is still per market — inspect the stream
status and wait for a snapshot before using a book.

## Access

Kalshi is a **read-only data entitlement**, granted separately from the trading venues. Holding
Polymarket or Predict.fun access does not include it. Market Data connections need a credential
with `stream.read` on an eligible paid plan — see [authentication](/authentication) and
[API credits](/api-credits#authenticated-websocket-credits).

[Native Kalshi market data](/api/market-data/kalshi-native) provides current books, catalogue metadata, public trades and native candles over REST. [Captured Kalshi order-book history](/api/market-data/kalshi-history) is available separately through REST with a Data credential and Kalshi data grant: point-in-time book reconstruction over content-addressed generations, with every gap disclosed. Continuous historical depth — the full change stream over an arbitrary range, and backfill further into the past — is being delivered in stages; a bounded Parquet export can be scoped with the team in the meantime. Captured history is not the live book feed.
