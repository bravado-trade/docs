Kalshi is a US event exchange regulated by the CFTC as a designated contract market. Contracts
settle at \$1 if the event happens and \$0 if it does not, so a live price reads as an implied
probability — the same shape as the other venues on this page. Unlike Polymarket and Predict.fun
it is not a conditional-token market on a public chain: contracts are exchange-listed instruments,
identified by a market ticker rather than an on-chain token id.

<Info>
  **The Kalshi endpoint is published and is not serving yet.** `GET /stream/capabilities` is the
  authoritative answer for what you can subscribe to today. For `kalshi` it reports
  `implemented: true` with `book_path` and `subscription` set, and `upstream_registered: false`
  with `reason: "upstream_not_registered"`.

  Those two facts are different and the `reason` is what separates them: the endpoint exists and
  is documented below, and no data is flowing through it. A subscription will not fail at
  connect — it will simply never deliver a book. Read the fields rather than this page.
</Info>

Kalshi is a **Market Data venue only**. There is no Kalshi trading, copy-trading or trader
analytics on Bravado, and none is in rollout — see [product coverage](#product-coverage) below.

## What is in rollout

Live order books, over the same authenticated WebSocket surface and the same message envelope as
the venues already documented in [multi-venue order books](/api/market-data/venue-order-books):
one socket, many assets multiplexed, prices and sizes as decimal strings.

| | |
| --- | --- |
| WebSocket URL | `wss://partner-api.bravadotrade.com/stream/kalshi/partner` |
| Subscription | `book:<asset>`, where `asset` is the Kalshi market ticker |
| Required scope | `stream.read` |
| Status today | published, **not serving** — `reason: "upstream_not_registered"` |

Everything in [Connect](/api/market-data/venue-order-books#subscribe) and
[Read the messages](/api/market-data/venue-order-books#read-the-messages) applies unchanged.

**What "not serving" means in practice.** The route accepts an authenticated subscription and
then delivers nothing, because no upstream is attached in this deployment. It does not answer
with an error, so a client that treats a quiet socket as a quiet market will wait indefinitely.
Poll `GET /stream/capabilities` and act on `upstream_registered`, not on the absence of frames.

## Checking the live state

`GET /stream/capabilities` is the contract for what this venue serves, per organisation, right
now. It separates three facts that are easy to read as one:

| Field | Means |
| --- | --- |
| `implemented` | Bravado has built the endpoint for this venue |
| `upstream_registered` | the venue's upstream is wired in this deployment |
| `entitled` | your organisation holds the entitlement |
| `reason` | which of the three is missing, when the venue is not usable |

While `implemented` is `false`, there is no path and no subscription to call. Treat a venue named
in that payload as a published status, not an endpoint.

## Access

Kalshi is a **read-only data entitlement**, granted separately from the trading venues. Holding
Polymarket or Predict.fun access does not include it. Market Data connections need a credential
with `stream.read` on an eligible paid plan — see [authentication](/authentication) and
[API credits](/api-credits#authenticated-websocket-credits).
