Bravado authenticates every request with an **HMAC-SHA256 signature**. You send three headers: your API key, a millisecond timestamp, and a signature computed over the request with your API secret. There are no cookies and no session flows, and the secret itself never travels over the wire. The only public endpoint that does not require authentication is `GET /healthz`.

This is the same scheme on both HTTP surfaces: the Trade API on `partner-api.bravadotrade.com` and the Trader Data API on `api.bravadotrade.com`. One client signs for both.

<Note>
  **The MCP server is the one exception.** It uses OAuth 2.1 rather than a signed request, because an AI client cannot hold a long-lived partner secret safely and cannot compute an HMAC signature. See [MCP server authorization](#mcp-server-authorization) below.
</Note>

<Warning>
  **Do not build on static bearer tokens.** A small number of Data API integrations still send `Authorization: Bearer`, and those specific tokens keep working through the migration window only. A key you create today is not one of them. On the Trade API the bearer fallback is a disabled pilot flag, so in production `Authorization: Bearer` is answered with `MISSING_AUTH_HEADERS` on every route.
</Warning>

## Getting your API key

Create and manage your API keys in the [Bravado console](https://console.bravadotrade.com/keys).

1. Sign in at [console.bravadotrade.com](https://console.bravadotrade.com/) and verify your email address.
2. Create a key. Its scopes follow the products enabled on your plan (see [API key scopes](#api-key-scopes) below).
3. Copy **both** values. The **key** identifies you and is sent as a header on every request. The **secret** signs those requests and is shown once, at creation, and never again.

Your plan sets how many keys you can keep active at once. The console shows the count beside your active keys.

<Warning>
  The `trade.withdraw` scope, which allows withdrawing pUSD to an external address, is **not included** in a standard partner key and must be explicitly requested and granted. Even a key with all other trade scopes cannot initiate withdrawals without it.
</Warning>

Store the secret securely. Never embed it in client-side JavaScript, commit it to a public repository, or log it to an unprotected output stream. Treat it with the same care as a private key, because that is what it is. If it leaks, revoke the key in the console: the signature scheme protects the secret in transit, not after disclosure.

## Making authenticated requests

Every request carries three headers:

```text
X-BRAVADO-API-KEY: <your key>
X-BRAVADO-TIMESTAMP: <milliseconds since the epoch>
X-BRAVADO-SIGNATURE: <hex HMAC-SHA256 of the payload below>
```

### The payload you sign

Four lines, joined by a single newline (`\n`), in this order:

```text
<timestamp>
<HTTP METHOD, uppercase>
<canonical path>
<SHA-256 hex of the request body>
```

Sign it with HMAC-SHA256 keyed by your API **secret**, and send the result as lowercase hex.

For a GET there is no body, so the fourth line is the SHA-256 of the empty string, which is always:

```text
e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```

### The canonical path

The third line is not the raw URL. Build it like this:

1. Take the path, percent-decoded once.
2. Strip a trailing slash, unless the path is just `/`.
3. Drop query parameters whose value is null or absent.
4. Sort the remaining parameters by key.
5. Percent-encode each key and value to **RFC 3986**, then join as `k=v&k=v`.

So `GET /v2/trade/orders/open/?token_id=123&venue=polymarket` signs as `/v2/trade/orders/open?token_id=123&venue=polymarket`.

<Warning>
  Two encoding details cause almost every `INVALID_SIGNATURE`.

  **RFC 3986 is not `encodeURIComponent`.** JavaScript leaves `! ' ( ) *` unencoded; RFC 3986 does not. Encode them yourself.

  **This is not form encoding.** A space is `%20`, never `+`.

  Both produce a request that looks correct and is rejected with no indication of which character was wrong.
</Warning>

### Examples

Each of these signs `GET /v2/trade/account`. Point them at `https://api.bravadotrade.com` and the same code signs the Trader Data API.

<CodeGroup>

```bash cURL
#!/usr/bin/env bash
set -euo pipefail

HOST="https://partner-api.bravadotrade.com"
CANONICAL_PATH="/v2/trade/account"          # no query, so already canonical
TS="$(( $(date +%s) * 1000 ))"

BODY_SHA="$(printf '' | openssl dgst -sha256 -hex | awk '{print $2}')"
PAYLOAD="$(printf '%s\n%s\n%s\n%s' "$TS" "GET" "$CANONICAL_PATH" "$BODY_SHA")"
SIG="$(printf '%s' "$PAYLOAD" | openssl dgst -sha256 -hmac "$BRAVADO_API_SECRET" -hex | awk '{print $2}')"

curl -s "$HOST$CANONICAL_PATH" \
  -H "X-BRAVADO-API-KEY: $BRAVADO_API_KEY" \
  -H "X-BRAVADO-TIMESTAMP: $TS" \
  -H "X-BRAVADO-SIGNATURE: $SIG"
```

```python Python
import hashlib
import hmac
import os
import time
import urllib.parse

import requests

HOST = "https://partner-api.bravadotrade.com"
KEY = os.environ["BRAVADO_API_KEY"]
SECRET = os.environ["BRAVADO_API_SECRET"]


def canonical_path(pathname: str, query: dict | None = None) -> str:
    path = urllib.parse.unquote(pathname)
    if len(path) > 1 and path.endswith("/"):
        path = path[:-1]
    items = sorted((k, str(v)) for k, v in (query or {}).items() if v is not None)
    if not items:
        return path
    qs = "&".join(
        f"{urllib.parse.quote(k, safe='')}={urllib.parse.quote(v, safe='')}"
        for k, v in items
    )
    return f"{path}?{qs}"


def signed_headers(method: str, cpath: str, body: str = "") -> dict:
    ts = str(int(time.time() * 1000))
    payload = "\n".join([ts, method, cpath, hashlib.sha256(body.encode()).hexdigest()])
    signature = hmac.new(SECRET.encode(), payload.encode(), hashlib.sha256).hexdigest()
    return {
        "X-BRAVADO-API-KEY": KEY,
        "X-BRAVADO-TIMESTAMP": ts,
        "X-BRAVADO-SIGNATURE": signature,
    }


cpath = canonical_path("/v2/trade/account")
response = requests.get(HOST + cpath, headers=signed_headers("GET", cpath))
print(response.json())
```

```javascript JavaScript
import { createHmac, createHash } from "node:crypto";

const HOST = "https://partner-api.bravadotrade.com";
const KEY = process.env.BRAVADO_API_KEY;
const SECRET = process.env.BRAVADO_API_SECRET;

/** RFC 3986: encodeURIComponent leaves ! ' ( ) * raw, and a space is %20, never +. */
const enc = (v) =>
  encodeURIComponent(v).replace(
    /[!'()*]/g,
    (c) => "%" + c.charCodeAt(0).toString(16).toUpperCase(),
  );

function canonicalPath(pathname, query = {}) {
  let path = decodeURIComponent(pathname);
  if (path.length > 1 && path.endsWith("/")) path = path.slice(0, -1);
  const entries = Object.entries(query)
    .filter(([, v]) => v !== undefined && v !== null)
    .map(([k, v]) => [k, String(v)])
    .sort(([a], [b]) => (a < b ? -1 : a > b ? 1 : 0));
  if (entries.length === 0) return path;
  return path + "?" + entries.map(([k, v]) => enc(k) + "=" + enc(v)).join("&");
}

async function call(method, pathname, { query = {}, body } = {}) {
  const bodyStr = body === undefined ? "" : JSON.stringify(body);
  const ts = String(Date.now());
  const cpath = canonicalPath(pathname, query);
  const payload = [
    ts,
    method,
    cpath,
    createHash("sha256").update(bodyStr).digest("hex"),
  ].join("\n");

  const headers = {
    "X-BRAVADO-API-KEY": KEY,
    "X-BRAVADO-TIMESTAMP": ts,
    "X-BRAVADO-SIGNATURE": createHmac("sha256", SECRET).update(payload).digest("hex"),
  };
  if (bodyStr) headers["Content-Type"] = "application/json";
  if (method !== "GET") headers["Idempotency-Key"] = crypto.randomUUID();

  const res = await fetch(HOST + cpath, { method, headers, body: bodyStr || undefined });
  return res.json();
}

console.log(await call("GET", "/v2/trade/account"));
```

```go Go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"io"
	"net/http"
	"os"
	"strconv"
	"strings"
	"time"
)

func signedHeaders(secret, method, canonicalPath, body string) map[string]string {
	ts := strconv.FormatInt(time.Now().UnixMilli(), 10)
	bodySum := sha256.Sum256([]byte(body))
	payload := strings.Join(
		[]string{ts, method, canonicalPath, hex.EncodeToString(bodySum[:])},
		"\n",
	)
	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(payload))
	return map[string]string{
		"X-BRAVADO-API-KEY":   os.Getenv("BRAVADO_API_KEY"),
		"X-BRAVADO-TIMESTAMP": ts,
		"X-BRAVADO-SIGNATURE": hex.EncodeToString(mac.Sum(nil)),
	}
}

func main() {
	const host, canonicalPath = "https://partner-api.bravadotrade.com", "/v2/trade/account"

	req, _ := http.NewRequest("GET", host+canonicalPath, nil)
	for k, v := range signedHeaders(os.Getenv("BRAVADO_API_SECRET"), "GET", canonicalPath, "") {
		req.Header.Set(k, v)
	}

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	out, _ := io.ReadAll(resp.Body)
	fmt.Println(string(out))
}
```

Read your key and secret from environment variables or a secrets manager. Never hardcode them inline.

### Clock skew

Your timestamp must be within **five minutes** of ours, in either direction. Outside that window the request is refused with `STALE_TIMESTAMP`, whatever the signature says, so that a captured request cannot be replayed indefinitely.

Send milliseconds, not seconds. A seconds-precision timestamp is roughly 56 years in the past and fails this check rather than the signature check, which is at least a clear error.

## API key scopes

Every Bravado API key is issued with one or more scopes. A request to an endpoint that requires a scope your key doesn't hold will be rejected with a `403 Forbidden` response.

| Scope | What it allows |
| --- | --- |
| `trade.read` | Read account snapshot, balances, positions, open orders, activity history, and active strategies |
| `trade.execute` | Place orders, redeem resolved positions, and split or merge outcome tokens |
| `trade.cancel` | Cancel a single order, cancel orders in batch, cancel all open orders, and cancel strategies |
| `trade.withdraw` | Withdraw pUSD from the trading wallet to an external address, **not included in `trade.execute`** |
| `trade.combos` | Access multi-leg RFQ parlays: quote, accept, and redeem combo positions, and read combo positions |
| `trade.users` | Provision and manage partner sub-users (white-label flow) |
| `analytics.read` | Read the [Trader Data API](/products/data-api) (`/trader-analytics/*`): leaderboards, trader profiles, PnL series, positions, trade history |
| `mcp.read` | Use the [MCP server](/products/mcp-server)'s curated analytics tools. Granted by the **MCP Server** product, which is separate from the Data API |
| `mcp.query` | Run read-only SQL through the MCP server's `run_sql` tool |

<Note>
  Scopes are not the only gate on the Data API. Each request's venue (Polymarket, or Predict.fun under `/predict/*`) must also be enabled on your partner account,, and your plan's credit allowance applies on top of both. See [API credits](/api-credits).
</Note>

Scopes are additive, a key can hold any combination. A key's scopes follow the products enabled on your account, so a scope you cannot see is one your plan does not include; the [console](https://console.bravadotrade.com/keys) shows which products are on.

## Master keys vs. user keys

Bravado supports two key archetypes that serve different purposes in a partner integration:

**Master keys** are issued at the partner level. They are not bound to a specific user wallet. A master key with the `trade.users` scope can call the user provisioning endpoints to create and manage sub-accounts on behalf of your platform. Use a master key in your backend services, never expose it to end users.

**Per-user keys** are bound to a specific provisioned user wallet. All trade activity executed with a per-user key is attributed to that wallet. These keys typically hold `trade.read`, `trade.execute`, and `trade.cancel` scopes, but not `trade.users`.

Use your master key to provision users and generate their keys. Use per-user keys to execute trades on their behalf.

## MCP server authorization

The [MCP server](/products/mcp-server) does not take an API key. It uses **OAuth 2.1** with PKCE, and access is granted by a human approving a consent screen rather than by pasting a secret into a client.

Why it differs from the rest of the API:

- An MCP client runs on someone's laptop or in a chat product. Handing it a partner master key would put a credential that can act for your whole organisation somewhere you cannot rotate or audit.
- Data API requests are HMAC-signed. An MCP client has no way to compute that signature, and giving it the secret to do so would defeat the point of signing.

The flow, from the client's point of view:

1. It reads `https://mcp.bravadotrade.com/.well-known/oauth-protected-resource` to find the authorization server.
2. It registers itself (RFC 7591 Dynamic Client Registration). Registering grants nothing on its own.
3. It sends you to [portal.bravadotrade.com](https://portal.bravadotrade.com/) to sign in and approve.
4. It receives a short-lived access token plus a rotating refresh token.

Tokens are scoped to `mcp.read` and `mcp.query` — the **MCP Server** product, which is separate from the Data API — and bound to the partner your portal account is linked to. They are audience-bound to the MCP server, so a token issued for it cannot be replayed against any other Bravado surface.

Revoke a connection from **Settings → Connected applications** in the portal at any time. Revocation takes effect immediately for the refresh token; an access token already issued is stateless and expires within five minutes.

## Authentication errors

Every refusal carries a machine-readable `code`. Match on that, never on the message: the messages are written for humans and are not part of the contract.

```json
{
  "error": "Unknown API key",
  "code": "INVALID_KEY",
  "request_id": "15e6b86e-a4c4-410f-a7b0-2e35fa29e9af"
}
```

Quote `request_id` when you contact support. It is also returned in the `X-Request-Id` header, including on requests that succeed.

### 401 Unauthorized

| Code | What went wrong |
| --- | --- |
| `MISSING_AUTH_HEADERS` | One of the three signing headers is absent. This is also what you get for `Authorization: Bearer` |
| `INVALID_KEY` | The key is not one we issued, or it has been revoked and needs rotating |
| `KEY_DISABLED` | The key exists but is expired or no longer active |
| `STALE_TIMESTAMP` | Your timestamp is not a whole number of milliseconds, or is more than five minutes from ours |
| `INVALID_SIGNATURE` | The headers are well formed and the key is real, but the signature does not match the payload we rebuilt |

`INVALID_SIGNATURE` almost always means the canonical path differs from what you signed. Check the trailing slash, the parameter ordering, and the two encoding rules above before suspecting the key.

Repeated failures from one IP are rate limited with `RATE_LIMITED`, so a client retrying a bad signature in a loop locks itself out. Fix the signature rather than retrying.

### 403 Forbidden

| Code | What went wrong |
| --- | --- |
| `INSUFFICIENT_SCOPE` | The key is valid but does not hold the scope the endpoint requires |
| `PARTNER_SUSPENDED` | The account itself is not active |
| `IP_NOT_ALLOWED` | The key has an IP allowlist and this request did not come from it |

Review your key's scopes by calling `GET /v2/trade/account` and inspecting the `api_key.scopes` array, or open the [console](https://console.bravadotrade.com/keys). A scope that is missing because your plan does not include the product is a billing question, not a support one: see [Billing](https://console.bravadotrade.com/billing).

## Idempotency keys

Every mutating request (`POST`, `PATCH`, and `DELETE`) requires an `Idempotency-Key` header. Bravado uses this key to deduplicate requests, so if a network timeout causes you to retry an operation, you won't accidentally create a second order or cancellation.

```text
Idempotency-Key: e4b9c1a2-38df-4f77-a3c5-012bd9e8f231
```

**Rules for idempotency keys:**

- Generate a fresh **UUID v4** for each new intended operation.
- Use the **same key** when retrying a request that failed with a network error or timeout.
- Do **not** reuse a key from a previous, successfully completed request to create a new one.
- Keys are scoped to your API token, the same UUID used by a different token is treated as a separate key.

<Tip>
  Most HTTP client libraries have a built-in UUID generator. In Python, use `str(uuid.uuid4())`. In Node.js, use `crypto.randomUUID()`. In Go, use the `github.com/google/uuid` package.
</Tip>

If you send a retry with the same idempotency key as a request that already succeeded, Bravado returns the original response with an `Idempotent-Replayed: true` header, no duplicate operation is performed.
