Bravado is a REST API platform that gives developers and partners direct, programmable access to Polymarket, the world's largest prediction market, running on Polygon. Whether you're building an algorithmic trading bot, a copy-trading product, a portfolio dashboard, or a white-label prediction market interface, Bravado provides the infrastructure to do it without managing low-level smart contract interactions.

Create and manage your API keys in the [Bravado Portal](https://portal.bravadotrade.com/).

## Bravado vs. Polymarket's native APIs

Bravado is not a passthrough. Each surface is purpose-built to do something Polymarket's native APIs do not, or do at a higher standard.

| Capability | Polymarket native | Bravado |
| --- | --- | --- |
| Order types | LIMIT, MARKET | LIMIT, MARKET, TWAP, ICEBERG, PEGGED, STOP\_LOSS, TAKE\_PROFIT, TRAILING\_STOP |
| Execution latency | Baseline | Lower, with server-side execution of advanced order types |
| Data accuracy and reconciliation | Baseline | Higher, with PMWAS-standardized PnL and full fill reconciliation |
| Rate limits | Public quotas | Higher per-partner quotas on the Analytics API |
| Copy-trading | Not available | First-class Copytrade API with configurable sizing modes |
| Historical PnL depth | Recent activity | Full wallet history from first trade, with cost-basis tracking |
| Tax reporting | Not available | Tax statements per wallet, US-format |
| Sub-account provisioning | Not available | Master-key flow for white-label integrations |
| Idempotency | Not enforced | Required `Idempotency-Key` on every mutating request |

## API surfaces

Bravado exposes three distinct API surfaces. Each is purpose-built for a different layer of a Polymarket application.

| API | Base URL | Description |
| --- | --- | --- |
| **Trade API v2** | `https://bravado-api-k7kaq.ondigitalocean.app/v2/trade` | Order execution, positions, balances, and user provisioning |
| **Copytrade API** | `https://bravado-api-k7kaq.ondigitalocean.app/v2/trade/copytrade` | Mirror fills from top traders with configurable sizing |
| **Analytics API** | `https://bravado-api-k7kaq.ondigitalocean.app` | Leaderboards, wallet PnL, and tax statements |

### Trade API v2

The Trade API is the core of Bravado. It handles the full order lifecycle — submission, monitoring, and cancellation — across a rich set of order types designed for both simple one-off trades and sophisticated algorithmic strategies.

**Supported order types:**

- **LIMIT** — Post a resting order at a specific price.
- **MARKET** — Fill immediately at the best available price.
- **TWAP** — Time-weighted average price execution, splitting a large order over a defined window.
- **ICEBERG** — Show only a slice of your full order size to the market.
- **PEGGED** — Track the best bid or ask dynamically.
- **STOP\_LOSS** — Trigger a market sell when price falls to your stop level.
- **TAKE\_PROFIT** — Trigger a market sell when price rises to your target.
- **TRAILING\_STOP** — Follow price upward and trigger when it reverses by a set amount.

The Trade API also handles account management: checking USDC and pUSD balances, reading open positions, reviewing activity history, and provisioning sub-users under a partner master key.

### Copytrade API

The Copytrade API lets you automatically mirror the fills of any Polymarket wallet. When your tracked trader executes a fill, Bravado replicates the trade on your behalf using configurable sizing logic — proportional, fixed, or capped. This powers social trading products and portfolio strategies without requiring you to monitor the chain yourself.

### Analytics API

The Analytics API surfaces Polymarket performance data at the wallet level. Use it to build leaderboards ranked by PnL or volume, inspect detailed trade history for any public wallet, and generate tax statements for realized gains. It works on any Polymarket address — not just those managed through Bravado.

## Key capabilities

- **Eight order types** spanning basic execution and advanced algorithmic strategies
- **Copy trading** with flexible per-strategy sizing controls
- **Wallet analytics** including historical PnL, volume, and market-level breakdowns
- **Tax statements** for realized gain/loss reporting
- **User provisioning** so partners can create and manage sub-accounts under a master key
- **Idempotent mutations** — every write endpoint accepts an `Idempotency-Key` to prevent duplicate orders

<Note>
  All numeric fields in API responses — including prices, PnL figures, sizes, and collateral amounts — are returned as **JSON strings**, not numbers. This preserves full decimal precision. Always parse these values using a `BigDecimal` (or equivalent arbitrary-precision) type in your application rather than a floating-point number.
</Note>
