Start with a signed account read, then choose the execution workflow your application needs. For live market data, use the [market-data quickstart](/quickstart).

## 1. Prepare your account and credential

Open [Trade API in the Console](https://console.bravadotrade.com/endpoints/trade). The product catalog is visible before an endpoint is configured. Execution requires the appropriate organisation access, key scopes, enabled venue and a ready trading account.

Save your public key and the secret revealed at creation in your local environment as `BRAVADO_API_KEY` and `BRAVADO_API_SECRET`. Use a per-user credential for account trading; use an appropriately scoped master credential for [user provisioning](/api/trade/account).

## 2. Choose the venue

Use `polymarket` or `predictfun` in the venue alias path. The example below reads Polymarket. Change the path to `/v2/trade/predictfun/account` for Predict.fun.

## 3. Run a signed request

Save this as `bravado.py` and run `python3 bravado.py`. It uses only the Python standard library and performs a GET account read.

```python
import hashlib
import hmac
import os
import time
import urllib.request

request_path = "/v2/trade/polymarket/account"
timestamp = str(int(time.time() * 1000))
body_hash = hashlib.sha256(b"").hexdigest()
payload = "\n".join([timestamp, "GET", request_path, body_hash])
signature = hmac.new(
    os.environ["BRAVADO_API_SECRET"].encode(),
    payload.encode(),
    hashlib.sha256,
).hexdigest()
request = urllib.request.Request(
    "https://partner-api.bravadotrade.com" + request_path,
    headers={
        "X-BRAVADO-API-KEY": os.environ["BRAVADO_API_KEY"],
        "X-BRAVADO-TIMESTAMP": timestamp,
        "X-BRAVADO-SIGNATURE": signature,
    },
)
with urllib.request.urlopen(request) as response:
    print(response.status, response.read().decode())
```

For TypeScript and cURL examples, open the [Console connection workbench](https://console.bravadotrade.com/endpoints/trade?section=connect). See [authentication](/authentication) for signing rules and errors.

## 4. Inspect readiness and balances

Review the [account response](/api/trade/account) and [positions](/api/trade/positions). Confirm the intended user, venue and collateral before submitting execution requests. A successful GET does not grant additional execution permissions.

## 5. Choose your execution workflow

| Workflow | Reference | Venue coverage |
| --- | --- | --- |
| Market and limit orders | [Orders](/api/trade/orders) | Polymarket and Predict.fun |
| Pegged, TWAP and iceberg | [Strategies](/api/trade/strategies) | Polymarket and Predict.fun |
| Conditional orders and brackets | [Trade API](/products/trade-api) | Polymarket |
| Multi-leg RFQ | [Combos](/api/combos/overview) | Polymarket; access required |
| Copy trading | [Copytrade](/api/copytrade/overview) | Polymarket; access required |
| Withdrawals | [Withdraw](/api/trade/withdraw) | Separate withdrawal scope required |

For writes, sign the exact serialized body and supply the route’s required `Idempotency-Key`. Keep that key for retries of the same operation. Review [Polymarket capabilities](/markets/polymarket/trade-api) and [Predict.fun capabilities](/markets/predict-fun/trade-api) before selecting an order type. Feature availability also depends on deployment and account access.
